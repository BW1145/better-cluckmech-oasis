# 更好的鸡械绿洲：开发指南

更新日期：2026-10-24。运行版本 **0.6.18**。版本号以 `src/CluckmechCoop.csproj` 和 `src/Plugin.cs` 为准。

## 运行代码与生命周期

- `Plugin` 负责补丁安装、场景接入与服务持有；`SceneLifecycle` 负责有序清理，`UnitLifecycle` 与 `UnitActionLifetime` 负责单位移除和异步动作失效。
- `ModulePreferences` 保存本机偏好；`ModuleRunState` 固定本局设置；`ModuleSaveStore` 处理附加存档。场景状态与本局进度分别清理。
- `NetworkObjects` 提供网络对象编号，`NetworkValues` 提供浮点有效性检查；`NetworkService` 处理设置会话；`TransferService` 处理转交；`OtherworldNetwork` 与 `OtherworldProtocol` 处理新角色指令和必要状态。
- `OtherworldTalentIds` 集中定义已发布的天赋编号，`OtherworldCatalog` 定义角色和天赋，`OtherworldRun` 保留本局数据字段；`OtherworldActor` 连接输入、技能与动作；`OtherworldActions` 执行效果，表现回调位于同类型的 `OtherworldActorPresentation` 分部，补丁入口位于 `OtherworldActorPatches`；属性修正位于 `OtherworldModifiers`、`OtherworldProgress` 与 `OtherworldStates`。
- `KamuiWorld`、`KamuiNavigation`、`KamuiIsolation` 负责空间和导航；`KamuiVisibility` 负责可见性；`KamuiSave` 保存本局阵地与囚犯。每个带土拥有自己的空间。
- `StratagemRules` 定义战备参数；`StratagemUnit` 执行战备行为；`StratagemPersistence` 负责空间内战备快照。`BronzeDragon` 系列负责青铜龙。

`KamuiPrefabs`负责空间模板身份；`OtherworldHitDisplay`、`StratagemHitDisplay`及状态反馈文件负责房主结算结果的客机显示。

## 主题支线接入

`ThemeBranchState` 保存支线身份、抽选、完成节点、事件与主线快照，归入现有 `RunProgress`；`ThemeMapCodec` 对原版地图字段及挑战/奖励资源ID编码；`ThemeBranchMaps` 复用原版页面与节点；`ThemeBranchEvents` 复用原版事件面板和联机决策；`ThemeBranchRuntime` 连接场景推进、原版保存、奖励出口和返回。

主机在原版地图RPC前使用现有设置通道发送本次支线状态；客机使用原版地图位置。奖励推进发生在奖励场景成功退出到地图时。第一阶段使用原版战斗场景承载，主题开关默认关闭；正式地图后续按稳定主题与节点身份接入。关联检查为 `ThemeBranches`、`ThemeBranchWiring`、`Modules` 和 `ModuleLifecycle`。

## 当前机制基线

玩法与数值参见 `使用说明.md`、`design/异界角色设计.md` 和 `design/青铜龙雕像.md`。近期代码基线：

- 佩丽卡闪链按普攻实际伤害命中累计，通常4次、瞬发回路2次。穿透命中不同敌人分别累计，空枪不累计，闪链独立判定暴击。
- 带土基础攻击70；火遁初始灼烧加成50%，每次鸡械强化再增加7%；不熄余烬将成长改为10%。
- 豪火灭却在长按进入空间时释放；短按在虚化结束时释放。剩余灼烧结算后移除，结算部分使用状态伤害。
- 神威输入、分段冲刺、导航及跨关保存已有专用检查。修改这些入口前追踪它们的直接调用方。

## 离线检查

统一入口为 `ValidateUpdate.ps1`，使用 `-List` 查看名称，使用 `-Select` 指定本次相关项。完整清单、私有资料依赖及检查层次见 `tests/CHECKS.md`。

保留的测试优先链接生产源码或读取最终程序集。原版源码仅由本机参数提供，不进入仓库和安装包。检查通过后不因打包、安装或发布而重跑。开发侧不启动游戏。

## 美术与音频制作

- 战备：`art/BuildStratagemAssets.py` 从 `art/StratagemParts` 和 `src/StratagemAssets` 中的制作输入生成 `stratagem-v2` 图集。七张单体PNG仍是制作输入。
- 新角色基础图集：`art/BuildOtherworldAssets.py`；独立技能图集：`art/BuildOtherworldVfx.py`。
- 新角色正式动作：`art/OtherworldRig/BuildProductionAtlas.py` 生成 `faithful-0/1`。动作入口和复现命令以该目录 `README.md` 为准。
- 运行音频位于 `src/MusicAssets`、`src/StratagemSounds` 与 `src/OtherworldSounds`。制作源文件位于 `art` 及 `cluckmech-music`。

## 打包与交付

主插件构建使用 `GameDir` 参数或 `CLUCKMECH_GAME_DIR`。`Package.ps1` 使用已有三个 Release DLL，复制加载器、运行音频、默认配置和玩家文档并检查完整包。

正式加载配置位于 `dependencies/Defaults/BepInEx.cfg`。`evidence` 为历史故障和画面证据，构建、打包均不依赖该目录。

`release` 仅保留当前完整包及展开目录；旧版本可从 GitHub Release 获取。`bin`、`obj`、`artifacts/checks` 是可重新生成的本地产物。存档备份、原图与故障记录分别保留，不作为发布输入。

安装前检查游戏已退出，保留现有配置。版本更新沿用完整包、安装、Git提交与Release流程。仅开发工具和文档整理时保留运行版本及已有DLL。

## 后续整理边界

角色主类和战备主类仍承载较多逻辑。天赋编号、网络对象编号与浮点检查已归于对应公共文件，角色表现和补丁入口已按文件分开。后续仅在功能修改涉及对应职责时再拆分技能执行或战备行为；一次只移动一个职责，保留序列化字段、Unity回调、补丁目标及调用顺序，检查直接受影响的入口。当前不为整理改写伤害、技能状态或保存协议。

历史实现和验证过程可通过Git历史及 `验证记录.md` 查阅。
